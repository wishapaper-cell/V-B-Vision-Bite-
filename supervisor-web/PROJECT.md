# 健康饮食管理端项目说明

## 定位

管理端是当前单仓库中的独立 Flask 应用，为运营、营养师或授权管理员提供用户与饮食数据治理能力。它与用户端使用不同的管理员数据库，并在本地原型阶段读取同一份用户业务 SQLite。

## 功能域

| 功能域 | 已实现能力 |
|---|---|
| 管理员 | 首次超级管理员、邀请注册、待审批账户、启停、登录失败限制 |
| 用户 | 搜索、详情、基础资料、健康史、过敏、饮食偏好、慢病、风险等级、状态、解绑、导出 |
| 饮食 | 全局查询、用户时间线、记录详情、克重/热量/宏量营养修正、删除 |
| 食物库 | 热量、宏量营养、矿物质、替代食物、单位、分类、上下架、导出 |
| 食谱 | 基本信息、原料、份数、营养、适用/忌用人群、上下架、删除、导出 |
| 反馈 | 工单分类、优先级、状态、管理员回复、解决时间、导出 |
| 系统 | 数据库状态、在线备份、审计日志 |

所有写操作均应经过管理员登录、CSRF 校验、角色/状态校验，并记录必要的审计信息。

## 数据模型

管理员数据库包含：

- `admins`：管理员身份、角色、启用状态与审批状态。
- `admin_invitations`：邀请摘要、有效期、使用和撤销状态。
- `audit_logs`：管理员、动作、目标、详情和来源 IP。
- `login_attempts`：登录限流与安全审计。

用户业务数据库由用户端创建，管理端只做向后兼容的增量迁移。除用户与饮食记录外，还包含 `recipes`、`recipe_ingredients` 和 `feedback_tickets`。

## 运行约定

规范启动入口是仓库根目录的 `scripts/dev/start-supervisor-web.ps1`，默认端口为 `5100`。默认数据路径位于 `.workspace/data/`，可通过 `USER_APP_DB_PATH` 与 `ADMIN_DB_PATH` 覆盖。

备份文件属于运行时数据，不应加入 Git。生产环境需要 HTTPS、集中认证、细粒度授权、数据库事务边界和统一 API，不能继续依赖跨进程共享 SQLite。
