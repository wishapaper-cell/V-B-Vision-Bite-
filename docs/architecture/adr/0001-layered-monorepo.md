# ADR-0001：采用分层单仓库结构

- 状态：Accepted
- 日期：2026-07-25

## 背景

迁移前，用户端、算法、监管端、Android 工程、设备联调工具、APK、日志、缓存和多个重复代码副本混合在顶层目录。部分代码位于嵌套 Git 仓库，数据库路径和启动路径不一致。

## 决策

采用分层单仓库结构：

- `apps/`：可部署应用。
- `services/`：后端和算法服务。
- `ml/`：训练代码。
- `tools/`：开发和设备联调工具。
- `docs/`：当前文档。
- `scripts/`：统一自动化。
- `artifacts/`：交付和调试产物。
- `legacy/`：迁移前历史仓库。
- `.workspace/`：本机数据和缓存。

迁移前的 `recognition_algorithm` 嵌套仓库整体保留到 `legacy/recognition-algorithm-repository/`，避免丢失历史。

## 影响

正面影响：

- 明确唯一开发基线。
- 数据、构建产物和源码分离。
- 启动和配置路径可统一。
- 更适合代码评审、CI 和后续服务化。

代价：

- 旧文档和外部脚本中的路径需要更新。
- Android 构建脚本需要适配新相对路径。
- 旧压缩包或快捷方式可能继续引用历史目录。

## 兼容策略

- 根目录保留 Rokid 后端兼容启动脚本。
- 历史仓库完整保留在 `legacy/`。
- 产品需求文档保留“迁移前路径”说明，同时使用新路径作为当前代码索引。
